# H200 AWAC 后训练运行命令

本文档给接手同学直接复制运行。

**H200 混训后训练的唯一执行入口（与仓库脚本一致，以此为准）：**

| 阶段 | 脚本（相对仓库根目录） |
|------|------------------------|
| Critic | `examples/calvin/train_files/h200_awac_critic_mixed_oneclick.sh` |
| Actor | `examples/calvin/train_files/h200_awac_actor_mixed_oneclick.sh` |

```text
Qwen3.5-4B PI-State BC (steps_30000)
-> merge rollout shards + expert allowlist（critic oneclick 内完成）
-> public expert + rollout 1:1 混训（data_mix=calvin_awac_mixed_h200）
-> dataloader 即时 reward/done（compute_rewards_on_the_fly=true）
-> critic 10k 步（save 每 1k）
-> actor 30k 步（save 每 5k，仅训 action head）
-> CALVIN eval / rollout
```

下文 §0–§3 的路径表与 readiness 在 **H200** 上有效；本地开发机通常没有这些目录，属正常。§4 / §7 为**单源 expert 备选**；§4b / §7b 与两个 oneclick 对齐。

核心原则：

- 不复制完整 CALVIN 数据集。
- 不修改 public parquet。
- 不使用 `assume_success_if_missing=true`。
- 混训必须用 `calvin_awac_mixed_h200` + `balance_datasets=true` + `episode_allowlists_path`（由 oneclick 生成）。
- 不把 9B `steps_25000` 写成 30k。

## 3. 严格 readiness 检查

这一步确认 BC、数据、state/action 维度和 on-the-fly reward/done 路线都满足 AWAC 入口要求。

注意：这里**不传** `--assume-success-if-missing`。当前数据 sampled parquet 已有真实 `success`，所以必须真实读取 success。

```bash
export OUT="/inspire/qb-ilm2/project/26summer-camp-10/26220216/starVLA_Project/logs/awac_readiness_onfly_$(date +%Y%m%d_%H%M%S)"
mkdir -p "$OUT"

"${STAR_VLA_PYTHON}" /inspire/qb-ilm2/project/26summer-camp-10/26220216/starVLA_Project/examples/calvin/scripts/inspect_awac_readiness.py \
  --batch-root /inspire/qb-ilm2/project/26summer-camp-10/26220216/starVLA_Project/logs/20260519_h200_server1_pi_state_30k_v1 \
  --data-root /inspire/qb-ilm2/project/26summer-camp-10/public/inspire_shared/calvin_abc_d \
  --dataset-name calvin_task_ABC_D \
  --data-mix calvin_abc_d_h200 \
  --expected-step 30000 \
  --job-expected-step server1_pi_state/qwen35_9b=25000 \
  --allow-on-the-fly-rewards \
  --json-out "$OUT/awac_readiness_strict_success.json" \
  > "$OUT/awac_readiness_strict_success.md"

echo "inspect_status=$?"
sed -n '1,300p' "$OUT/awac_readiness_strict_success.md"
```

必须看到：

- `inspect_status=0`
- `overall: PASS`
- `success labels: PASS`
- `assume_success_if_missing: False`
- `AWAC reward preprocessing: PASS`
- `state metadata dim: state dim 8`
- `action metadata dim: action dim 7`

如果这里不是 PASS，不要开 critic。

## 6. Critic 中断后的处理

当前 `train_awac_critic.py` 没有严格 resume 参数。不要把重启训练说成“从旧 checkpoint 继续训练”。

先看进程是否还在：

```bash
ps -ef | grep -E 'train_awac_critic.py|accelerate.commands.launch' | grep -v grep || true
```

再看已经保存了哪些 critic checkpoint：

```bash
export CRITIC_RUN=/inspire/qb-ilm2/project/26summer-camp-10/26220216/starVLA_Project/logs/20260520_awac_pi_state_onfly/awac_critic_pi_state_qwen35_4b_bc30k_onfly
find "${CRITIC_RUN}/checkpoints" -maxdepth 1 -type f -name 'steps_*_critic.pt' -print | sort || true
```

处理原则：

- 如果进程还在，继续等。
- 如果进程已死，已有 checkpoint 只能作为不完整记录。
- 若必须真正续训，需要先实现并验证 resume 逻辑。
- 若只是重新跑，换新 `run_id`，不要覆盖旧目录。

重新跑示例：

```bash
export run_root_dir=/inspire/qb-ilm2/project/26summer-camp-10/26220216/starVLA_Project/logs/20260520_awac_pi_state_onfly
export run_id=awac_critic_pi_state_qwen35_4b_bc30k_onfly_restart1
bash /inspire/qb-ilm2/project/26summer-camp-10/26220216/starVLA_Project/examples/calvin/train_files/run_calvin_awac_critic.sh
```
