# 10 源码阅读索引

## 学习目标

提供一张从算法问题到源码文件的索引表。需要排查训练、评测、Adapter、LoRA、CALVIN failure 时，先从这里定位入口。

## 算法直觉

源码阅读不要从文件树随机看，而要沿任务链路看：

```text
配置 -> 模型注册 -> VLM 输入 -> action head -> 训练循环
    -> checkpoint -> server -> eval -> failure video
```

## 输入输出张量 / 数据结构

最重要的统一结构：

```text
framework.forward(examples) -> {"action_loss": Tensor}
framework.predict_action(examples) -> {"normalized_actions": ndarray[B,T,D]}
PolicyServerWrapper.predict_action(...) -> {"actions": ndarray[B,T,D]}
CalvinPolicyClient.step(...) -> ndarray[D]
```

## 训练时怎么走

训练入口优先看：

```text
examples/calvin/train_files/run_calvin_qwen35_oft_smoke.sh
examples/calvin/train_files/starvla_train_calvin_qwen35_oft_smoke.yaml
starVLA/training/train_starvla.py
```

源码阅读顺序：

1. YAML 看 `framework.name` 和 `base_vlm`。
2. `build_framework` 看具体类。
3. framework `__init__` 看组件。
4. framework `forward` 看 loss。
5. `train_starvla.py` 看保存和日志。

## 推理时怎么走

推理入口优先看：

```text
examples/calvin/eval_files/run_policy_server_debug.sh
deployment/model_server/server_policy.py
deployment/model_server/policy_wrapper.py
examples/calvin/eval_files/eval_calvin_debug.sh
examples/calvin/eval_files/eval_calvin.py
```

源码阅读顺序：

1. server 加载 checkpoint。
2. wrapper 读取 metadata。
3. eval client 发 image/lang。
4. framework 输出 normalized actions。
5. norm processor 反归一化。
6. CALVIN env 执行动作。
7. task oracle 判断成功。

## 与 CALVIN 任务的关系

CALVIN 分数的真实来源是 eval oracle，所以任何算法改动最终都要落到：

- Task1~5 成功率。
- Average sequence length。
- failure mp4。
- 是否能在未见环境 D 泛化。

源码阅读时要不断问：这个改动会影响图像、语言、动作、归一化、server 还是 eval？

## 当前项目中的风险点

- `Plan` 中的路线选择必须服从源码现实，不能把不存在的 LoRA/FAST 链路当已可用。
- `QwenAdapter` 是已有实现，但 Qwen3.5 兼容性仍需 smoke。
- `QwenFast` 和 Qwen3.5 普通权重不直接兼容。
- `QwenPI` 本地 OOM，H200 要先短测。

## 可以改进的位置

- 给每条路线建立最小 smoke checklist。
- 给 `QwenAdapter` 做 Qwen3.5 token id 兼容修正。
- 给 LoRA 写单独工程设计，不混入 OFT 主线。
- 给 eval 增加动作数值 dump，配合 mp4 排查 failure。
