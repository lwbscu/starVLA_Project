# 08 训练评测闭环

## 学习目标

理解一个 checkpoint 如何从训练产物变成 CALVIN 环境中的实际动作，并知道每个环节出了问题应该看哪个源码。

## 算法直觉

VLA 不是训练 loss 游戏。真正闭环是：

```text
train -> checkpoint -> server load -> websocket infer
      -> unnormalize -> CALVIN env.step -> task oracle -> results/mp4
```

任何一个环节错，都会表现为 eval 失败。

## 输入输出张量 / 数据结构

训练保存：

```text
run_dir/
  config.yaml
  config.full.yaml
  dataset_statistics.json
  checkpoints/steps_xxx_pytorch_model.pt
```

server metadata：

```text
{
  "action_chunk_size": 8,
  "available_unnorm_keys": ["franka"],
  "default_unnorm_key": "franka",
  "action_keys": [...],
  "state_keys": [...]
}
```

server 输出：

```text
{"actions": np.ndarray[B, T, D]}  # 已反归一化
```

CALVIN client 最终动作：

```text
np.ndarray[7] = [dx, dy, dz, droll, dpitch, dyaw, gripper]
```

## 训练时怎么走

训练时关键产物是 checkpoint 和 normalization stats。`dataset_statistics.json` 不是辅助文件，而是 eval 必需文件。没有它，server 无法把 normalized action 还原成环境动作。

`train_starvla.py` 中 `_save_checkpoint` 会保存模型参数，配置快照由 config tracker 保存。当前 policy server 依赖 run dir 结构向上寻找这些文件。

## 推理时怎么走

`server_policy.py` 创建 `PolicyServerWrapper`：

1. `baseframework.from_pretrained(ckpt_path)` 重建模型。
2. 读取 config，确定 `action_horizon`。
3. 读取 `dataset_statistics.json`。
4. 创建 `PolicyNormProcessor`。
5. websocket server 接受 client 请求。

`PolicyServerWrapper.predict_action`：

1. 调 framework `predict_action` 得到 normalized actions。
2. 调 `PolicyNormProcessor.unapply_actions` 反归一化。
3. 返回环境可执行 action chunk。

CALVIN eval client：

1. 将 `rgb_static` 和 `rgb_gripper` resize。
2. 构造 `{"image": [image, wrist_image], "lang": instruction}`。
3. 用 websocket 调 server。
4. 按 step count 从 action chunk 取动作。

## 与 CALVIN 任务的关系

CALVIN 的指标来自 `task_oracle`，不是来自模型自己判断。即使模型语言理解看似正确，只要实际动作没有让环境状态满足 oracle 条件，就算失败。

## 当前项目中的风险点

- `action_chunk_size` 与训练 `action_horizon` 不一致会导致 chunk 调度错误。
- `available_unnorm_keys` 不含 `franka` 会导致反归一化失败。
- train/eval image resize 不一致会导致视觉分布偏移。
- state 训练和 eval 不一致会导致模型依赖缺失输入。
- checkpoint 可以加载不代表动作正确，必须看 mp4。

## 可以改进的位置

- 每次 eval 自动保存 server metadata 到 eval log。
- 每个 mp4 文件名包含 sequence/subtask/success。
- 对第一帧和第一组 raw action 记录数值，用于判断动作尺度。
- 在 eval 前做一次 dry-run：输出 normalized action min/max。
