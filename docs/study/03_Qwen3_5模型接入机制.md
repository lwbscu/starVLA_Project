# 03 Qwen3.5 模型接入机制

## 学习目标

理解 StarVLA 如何把 HuggingFace Qwen3.5 包装成统一的 VLM backbone，以及它如何为 OFT/Adapter/PI/GR00T 提供视觉语言 hidden states。

## 算法直觉

在 VLA 中，Qwen3.5 不直接输出机器人动作。它负责把多视角图像和语言指令编码成语义视觉特征，action head 再把这些特征映射成动作。当前两天实训的关键不是训练 Qwen3.5 本体，而是利用它已有的视觉语言能力，训练轻量 action head。

## 输入输出张量 / 数据结构

输入：

```text
images: List[List[PIL.Image]]
instructions: List[str]
solutions: Optional[List[str]]
```

`build_qwenvl_inputs` 输出 HuggingFace processor 的 batch inputs，常见字段包括：

```text
input_ids
attention_mask
pixel_values
image_grid_thw
labels  # 仅 FAST/solutions 场景需要
```

Qwen forward 输出：

```text
CausalLMOutputWithPast
hidden_states: Optional[List[Tensor]]
logits
loss
```

OFT/Adapter/PI 这类 action head 主要消费 `hidden_states`。

## 训练时怎么走

`get_vlm_model(config)` 根据 `framework.qwenvl.base_vlm` 字符串选择后端：

```python
elif "Qwen3.5" in vlm_name:
    from .QWen3_5 import _QWen3_5_VL_Interface
    return _QWen3_5_VL_Interface(config)
```

`_QWen3_5_VL_Interface.__init__` 做：

1. 从 config 读取 `base_vlm`。
2. 从 config 读取 `attn_implementation`，默认 `sdpa`。
3. 如果请求 `flash_attention_2` 但没有 `flash_attn`，回退到 `sdpa`。
4. 调 `Qwen3_5ForConditionalGeneration.from_pretrained(...)`。
5. 调 `AutoProcessor.from_pretrained(...)`。
6. 设置 `processor.tokenizer.padding_side = "left"`。
7. 对齐 `self.model.config.hidden_size = self.model.config.text_config.hidden_size`。

训练时 framework 调：

```python
qwen_inputs = qwen_vl_interface.build_qwenvl_inputs(images, instructions)
outputs = qwen_vl_interface(..., output_hidden_states=True)
```

## 推理时怎么走

policy server 传入：

```text
example = {"image": [static, wrist], "lang": instruction}
```

framework 的 `predict_action` 会再次调用 `build_qwenvl_inputs`，然后用 Qwen3.5 编码图像和语言。不同 action head 对 hidden state 的用法不同：

- OFT：通常取最后 hidden state。
- Adapter：插入 action query token，再取 action query 对应 hidden state。
- PI/GR00T：把 hidden state 输入 DiT/Flow Matching 类动作模型。
- FAST：走语言模型生成 action token，但要求 tokenizer 和模型含 action special tokens。

## 与 CALVIN 任务的关系

CALVIN 指令是自然语言，环境是多视角图像。Qwen3.5 的价值在于把“turn off lightbulb”“open drawer”“rotate block”等语义和图像目标区域对齐。若 backbone 冻结，模型是否能做对动作，主要取决于 action head 能否从 hidden state 中读出任务相关控制信号。

## 当前项目中的风险点

- Qwen3.5 普通权重没有 action special tokens，不能直接跑 QwenFast。
- 本地默认 `sdpa` 更稳；`flash_attention_2` 只有在导入和 forward 都成功时才启用。
- 全参数训练 Qwen3.5 风险高，导师也明确不建议。
- `build_qwenvl_inputs` 的 chat template 决定语言格式，prompt 改动会影响 action head 学到的条件分布。

## 可以改进的位置

- 给 Qwen3.5 wrapper 加一个最小 forward 检查脚本，验证 image/lang -> hidden_states。
- 记录每条训练 run 的 `attn_implementation`。
- 若做 Adapter/FAST，单独检查 image token id 和 action token id 是否与 Qwen3.5 匹配。
